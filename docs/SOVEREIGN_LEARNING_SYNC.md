# Path: docs/SOVEREIGN_LEARNING_SYNC.md\n# Sovereign Learning Sync\n\nCada PC continua a ser um nó soberano. A sincronização é apenas um mecanismo opcional para trocar aprendizagem curada entre máquinas.\n\nArquitetura:\nPC A -> sync opcional -> Supabase -> sync opcional -> PC B\n\nO PC local é a fonte de verdade operacional. A cloud é apenas ponte/cópia de aprendizagem.\n\nPor defeito apenas estes artefactos são elegíveis:\n- radar/state_signature_learning.jsonl\n- radar/state_outcomes.jsonl\n- radar/l2_oos_validation.json\n- radar/capital_opportunities.jsonl\n- research/knowledge.jsonl\n\nNão são sincronizados posições, ordens, execution intents, saldos, credenciais, API keys, RealModeGuard, logs privados ou configuração local.\n\nNão existe loop permanente. O sync é explícito/manual nesta fase. Um futuro agendamento Windows poderá fazer, por exemplo, um pull/push diário sem transformar a cloud em dependência.\n\nNa primeira instalação pode existir um pull inicial opcional. Sem Internet, o PC continua a arrancar e trabalhar localmente.\n\nCada artefacto usa SHA-256. Conteúdo remoto inválido, fora da whitelist ou mais antigo que o ficheiro local é ignorado. Escritas remotas para o PC são atómicas.\n\nBackend inicial: Supabase REST API. Não é necessário SDK adicional. O runtime só ativa esta camada quando a configuração estiver explicitamente ligada e a chave de sync existir.\n\nSchema mínimo esperado no Supabase:\n\ncreate table if not exists public.shared_learning_artifacts (\n  owner_id text not null,\n  artifact text not null,\n  sha256 text not null,\n  bytes integer not null,\n  content text not null,\n  source_node_id text not null,\n  updated_at bigint not null,\n  created_at timestamptz not null default now(),\n  primary key (owner_id, artifact, sha256)\n);\n\nVercel não é necessária para o funcionamento do trader nem para esta primeira camada de sync. Pode ser usada mais tarde como relay/cockpit web substituível.\n\nEm setembro de 2026 o Vercel Hobby custa $0, mas a própria Vercel classifica Hobby como uso pessoal/não comercial. Como o objetivo final é receita, não devemos criar dependência comercial do runtime em Hobby.\n\nSupabase Free é adequado para esta fase de aprendizagem pequena. A documentação atual indica 500 MB de base de dados por projeto, 1 GB de Storage e limites de egress; projetos Free podem ser pausados após inatividade.\n\nAntes de REAL, conhecimento sincronizado é apenas evidência auxiliar. Cada PC tem de voltar a estudar/validar localmente, incluindo OOS, custos e regimes, antes de qualquer promoção.
